# Согласование стратегий

1. Продуктовая стратегия: наблюдаемый outcome, аудитория/ситуация/JTBD, реальные альтернативы, диагноз, возможности до решений, направление, явные стратегические отказы, необходимые изменения, механизм пользы, экономика и неопределённости.
2. Коммуникационная: момент выбора, барьер понимания/доверия/выбора, конкурентная рамка, сообщение, proof points, ограничения, роль каналов и действие аудитории. Календарь постов не является стратегией.
3. Для каждого обещания заполни матрицу: возможность уже есть / планируется / отсутствует; `E-*`; допустимая формулировка; проверка понимания. Планируемую функцию нельзя обещать как действующую.
4. План проверки содержит направление изменения, определение и знаменатель primary metric, базу/контроль, сегмент, период, минимально полезный эффект, достаточность данных, guardrails, вред и правило решения. Перед выдачей примени `knowledge/methods/metrics-economics-experiments.md`: правдивый контроль, полный знаменатель с неуспехами, совместимый календарь набора/созревания/readout и однозначная inconclusive-ветка.
5. Качественный тест понимания проверяет понимание, а не спрос. Синтетические респонденты генерируют гипотезы, но не доказывают распространённость.
6. Проверь реализуемость: ключевые зависимости, доступные люди/бюджет/время, технические и правовые ограничения, предполагаемая роль владельца. Неподтверждённый владелец остаётся `предложен`, не `назначен`.
7. Для ведущей неопределённости поставь перед дорогим пилотом самую дешёвую проверку, способную опровергнуть механизм, обещание или выполнимость. Зафиксируй результат, который остановит направление.

Если оснований мало, предложи последовательность измерений; не заполняй числа правдоподобными догадками.
