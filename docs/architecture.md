# Архитектура

## Граница системы

Агентом является LLM внутри Cursor/Codex, усиленная инструментами среды. Репозиторий — переносимый harness: инструкции, подгружаемые процедуры, методы, детерминированный CLI и состояние. Здесь нет цикла вызова модели, daemon, web UI или фонового планировщика.

```text
человек → LLM среды → выбирает skill / web / CLI / файлы
                      ↓
 outcome → diagnoses → opportunities → options → recommendation + memo
                ↑          source → extraction → claim → conclusion
                                                         ↓
                                    human decision → commitments
                                                         ↓
                 new source → revision → semantic recompute → new human choice
```

Рекомендация сравнивается с ближайшей реалистичной альтернативой. Критичные допущения получают условия смены и, когда определены формула и входы, пороги/чувствительность. Иначе агент пишет наблюдаемое условие без псевдоточного числа. Перед дорогим тестом выбирается самая дешёвая проверка, которая может опровергнуть ведущий механизм или ограничение.

## Разделение контекста

- Постоянные правила: `AGENTS.md`.
- Методы по требованию: `skills/`, `knowledge/`.
- Первичные материалы: `projects/<case>/sources/originals/`.
- Машинное извлечение: `sources/extracts/`; оно не считается фактом автоматически.
- Состояние: короткий cold-resume блок `state.md` + канонические CSV/JSON. Старый ответ не является источником.
- Результат: `options.md`, `strategy.md`; `decision-memo.md` — одностраничная проекция для руководителя. Подробные основания остаются по ID; memo не становится источником.
- История: decisions/revisions/operations append-only по смыслу; коррекция создаёт событие и impact.

## Доказательства и поправки

`S-*` описывает источник, hashes оригинала и извлечения, право, дату, полноту и gaps. `E-*` различает fact/hypothesis/forecast/interpretation и несёт source-qualified locator (`S-001#...`). `C-*` связывает вывод с основаниями, альтернативным объяснением и change condition. `D-*` фиксирует явный человеческий или явно simulated выбор.

Команда `revise` сначала сохраняет существующие brief/options/strategy/memo/state побайтно в `revisions/R-*-before/`, затем меняет текущий статус утверждения, добавляет запись истории, помечает зависимые выводы и перечисляет исторические решения и обязательства. Новый факт не наследует citations молча: нужны новые ссылки или явное обоснование reuse. Multi-file revision сначала оставляет pending manifest с версиями before/after; `check` требует явно завершить или откатить частичную запись. Затем LLM обязана смыслово пересчитать выводы, парное сравнение, рекомендацию, обе стратегии, обещания и memo. Код и LLM не меняют историческое решение: затронутый выбор требует нового явного ответа человека и новой append-only записи. Git полезен как дополнительная история, но агентная модель данных не зависит от Git.

## Импорт

TXT и Markdown (`.md`/`.markdown`) используют одно построчное извлечение без выполнения разметки и переходов по ссылкам. Новая schema 1.1 добавляет производный memo; 1.0 допускает его отсутствие. Неизвестная schema/type — явная ошибка, а не 1.0 по умолчанию.

- PDF: внешний `pdftotext -layout`, locator `page:N,line:M`; пустой слой — gap, OCR не запускается молча.
- DOCX: OOXML основного документа, `paragraph:N`, `table:N!R#C#`; изображения/комментарии объявлены gap.
- CSV: `row:N,column:name` и физические строки для multiline record, единый detected dialect в ingest/profile/retention, обнаружение неполных строк.
- XLSX: каждый лист/адрес, formula/cached value и style ID; формулы и смысл стилей не вычисляются.
- HTML/web: статический текст блочных и смысловых элементов (`div[1]`, `h1[1]`, `p[2]`); скрипты/стили отбрасываются, граница static-only всегда записана. `text/plain` разбирается построчно. URL — HTTPS, явный allowlist, сохранение обычных query parameters, явная redaction секретоподобных, запрет непубличных DNS-адресов и повторная проверка redirects.

Для локального web-источника URL не нужен: разрешённый snapshot импортируется как HTML. Для динамических страниц текущий extractor может быть неполным; сохраняется gap, а не «успех».

## Устойчивость и стоимость

Операция сначала `in_progress`, затем `succeeded`, `failed` или `outcome_unknown`. `recover` не повторяет работу: оно переводит незавершённое в неизвестный исход. После фактической проверки `resolve` добавляет связанную строку, сохраняя unknown в истории. Ingest сначала пишет staged artifacts и pending manifest, поэтому сбой либо не оставляет источник, либо становится обнаруживаемым и восстанавливаемым. Стоимость обязательна как статус, даже если число недоступно. Внешние побочные эффекты не входят в CLI.

## Почему один ведущий агент

Один автор меняет реестры. Исследователь или критик из отдельной сессии может проверить спорное основание без права записи; ведущий сохраняет значимое возражение и свой ответ в текущем кейсе. Если среда не поддерживает субагентов, тот же промпт работает как самопроверка. Ни большинство голосов, ни успешная команда не принимают решение за руководителя.

## Что взято из Ouroboros

Разобраны [SYSTEM.md: Dialogue, Decision Loop, Delegation, Workmanship](https://github.com/razzant/ouroboros/blob/4be731ffcd2990acff55fb746b0daa073c22d5af/prompts/SYSTEM.md) и [BIBLE.md: P1, P2, P3, P5, P7](https://github.com/razzant/ouroboros/blob/4be731ffcd2990acff55fb746b0daa073c22d5af/BIBLE.md). Здесь применены принципы, не универсальная личность и не текст системного промпта хоста.

| Идея | Что видит руководитель | Где исполняется |
|---|---|---|
| Способ действия выбирает модель | На «почему такой вывод?» — фрагмент источника и ответ, а не повторный цикл исследования. При новых данных — пересмотр. | [Корневой промпт](../AGENTS.md), затем один нужный навык |
| Память не заменяет исходное свидетельство | В новом чате старая заметка доступна, но её слова не делают решение принятым. Рядом — факты из реестров и адреса оригиналов. | `strategist.py resume`; представление строится при чтении, не записывается в папку |
| Замечание критика — проверяемое возражение, не вето | Можно увидеть, какой расчёт оспорен, что перепроверено и почему совет изменён или сохранён. | [Промпт проверки](../skills/review-decision/challenge.md); без второй сессии — явно самопроверка |
| Исправлять причину сбоя, а не только итоговый текст | После поправки можно сравнить старый и новый совет. Невозможно получить новый выбор руководителя простым пересчётом прогноза. | Существующий `revise` до правок; после него LLM проверяет связанные выводы и обещания |

`revise`, журнал операций, четыре варианта, шесть навыков и разделение «рекомендация ≠ решение» уже были в v0.3. Изменение этой итерации — компактный вход в агентный цикл, команда возврата, предметная проверка совета и [отдельная локальная память одной команды](portfolio-memory.md). Аналог разделения общих знаний и проектной памяти Ouroboros: отдельный кейс остаётся владельцем фактов и выбора, общий слой хранит только отобранный человеком или с его разрешения прецедент. Не переносились daemon, планировщик, самоизменение, общая память разных клиентов, обязательная панель моделей и автоматическое выполнение решений.
