# Варианты

1. **Оставить как есть.** Сохранить таблицу и встречу; экономит разработку. Возражение: возможный ущерб останется невидимым. Условие пересмотра: измеримые просрочки/время.
2. **Улучшить без автоматизации.** Две недели измерять своевременность, время встречи и причины запросов. Возражение: наблюдение само по себе не улучшит опыт.
3. **Повернуть к ручному тесту механизма.** После baseline отправлять согласившимся ручные напоминания; сравнить своевременность и раздражение. Возражение: ручной канал не докажет экономику бота.
4. **Закрыть направление.** Не возвращаться без заданного порога ущерба. Возражение: три сигнала могут указывать на реальную проблему.

Рекомендация агента: вариант 2, затем условно 3. Решение человека: `pending`.
