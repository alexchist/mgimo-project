# Как вспомнить решение из другого проекта

`resume` отвечает на вопрос «где мы остановились **в этом кейсе**?». `precedent` — на другой: «встречалось ли такое **в других кейсах нашей команды**?». Это необязательная локальная картотека для проектов в `projects/` одной рабочей копии. Новая папка начинает с пустой памяти; чужие чаты не импортируются.

Скажите агенту: **«Запомни для остальных проектов, что расчёт окупаемости пилота зависел от оценки поставщика. Напомни проверить договорную цену, если мы снова будем сравнивать пилот с ручной услугой».** Агент выбирает конкретный `C-*` (вывод) или `D-*` (решение) и записывает краткую формулировку и условие применимости. Если решение было рекомендацией или симуляцией, это видно и при последующем чтении. Запись не изменяет исходный проект.

## Попробовать локально

Из корня репозитория, **на новой учебной копии**, не поверх своего кейса. В Linux/macOS можно взять сохранённый синтетический пример:

```sh
mkdir -p projects && test ! -e projects/lesson-demo && cp -R examples/demo projects/lesson-demo
python3 tools/precedent.py remember lesson-demo --ref D-001 --topic "обещание продукта" --note "До теста коммуникации отделить доступные функции от запланированных" --when "Если решение опирается на продуктовый roadmap"
```

Откройте **новый чат** той же рабочей копии для другого кейса и спросите: «Что мы уже решали про обещания продукта? Было ли это настоящим решением?» Команда для проверки:

```sh
python3 tools/precedent.py find обещание
```

Ответ содержит `source_ref: projects/lesson-demo#D-001` и `decision_kind: simulated`. Это означает «в учебном сценарии такой вариант моделировали», а не «руководитель одобрил». Новому проекту всё равно нужны свои сведения о том, какие функции доступны. Поиск — по словам и фрагментам текста без учёта регистра, не по смысловой близости.

## Не путать совпадение с актуальностью

При чтении сравниваются сохранённые отпечатки связанных строк реестров: решение → выводы → утверждения. `matches` означает совпадение строк, **не проверку первоисточника или текущего рынка**. `changed` — запись или её основания изменились, `requires_recheck` — строки те же, но в них уже есть сигнал к пересмотру; `unavailable` — исходную цепочку сейчас не удалось прочитать. Для использования совета откройте основание и проверьте применимость; при расхождении не делайте автоматической замены в новом проекте. Добавление другого решения не переписывает историю этого решения.

Отзыв не стирает прошлое (подставьте `id` из ответа `remember`):

```sh
python3 tools/precedent.py retire P-0001 --reason "Условия пилота изменились"
python3 tools/precedent.py find --include-retired
```

Обычный поиск больше не предлагает отозванное. Для замены отзовите старую заметку и сохраните новую с действующим основанием. Удалённый или перенесённый исходный кейс оставит ссылку непроверенной, а не «по-прежнему подтверждённой».

## Граница обмена

Записи остаются в `.portfolio/precedents.json` и по умолчанию исключены из Git. CLI не копирует туда исходные документы и строки CSV. Однако `--note`, `--topic`, `--when`, имена проектов и причина отзыва видны всем, у кого есть доступ к этой копии. Не записывайте в них персональные данные, коммерческие условия конкретного клиента или секреты. Отзыв не является удалением персональных данных. Отдельные клиенты — отдельные рабочие копии; `.gitignore` не даёт разграничения доступа и не защищает от ручной отправки. В облачной IDE прочитанная заметка может уйти провайдеру модели.

Команды запускаются из корня. Для переноса на другой компьютер скопируйте приватно `.portfolio/` и разрешённые исходные кейсы с прежними путями; один Git-клон памяти не восстановит. Одновременно пишет только один процесс. Если запись была аварийно прервана, не повторяйте её вслепую: после завершения всех пишущих процессов сначала прочитайте `find --include-retired`; оставшуюся `.portfolio/.precedents.lock` можно снять вручную.
