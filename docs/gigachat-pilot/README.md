# Помогают ли инструкции Стратега модели GigaChat?

**В этом пилоте — не в главном.** GigaChat-3-Lightning с методиками дал более подробное обоснование, но ни разу не посчитал правильно итог выбора. При проверке письма критик дважды одобрил неподтверждённое обещание. Давать модели больше инструкций вместо проверки результата я бы не стал.

18 ноября 2026, Linux, прямой GigaChat API через `gigachat==0.2.3`. Все 15 успешных ответов API, включая промежуточные вызовы функций, назвали `GigaChat-3-Lightning:32.4.16.3`. Это **10 независимых по истории диалогов**, не 10 разных задач. Материалы синтетические. Не тестировались GigaChat Pro/Ultra, графическая IDE, изменения файлов, память и холодное продолжение.

## Сначала — один и тот же текст с методикой и без неё

В четырёх условиях по два повтора. Вопрос и первоисточники внутри каждой пары байтово одинаковы; условия различаются только дополнением к системной инструкции. Так эффект промпта не смешивается с тем, нашёл ли агент CSV. Температура 0,2, потолок 2 200 токенов ответа, без инструментов, истории и обратной связи между повторами. Порядок обращён во втором повторе. [Критерии и состав](protocol.md) · [сборка точных запросов](run.py) · [исходные ответы и метаданные каждого](runs/).

| Задача | Без методики | С методикой |
|---|---|---|
| Экономика, два ответа | [E0-1](runs/E0-1.md): назвал 144 тыс. ₽ затратой **за пилот**, хотя это за месяц. [E0-2](runs/E0-2.md): предложил подтверждение спроса от 30 пользователей как экономическое условие. Ни в одном нет полного результата и верной точки окупаемости. | [E1-1](runs/E1-1.md): верные 20% маржи до постоянных затрат, но неверный порог 45–50 аккаунтов. [E1-2](runs/E1-2.md): верные 432 тыс. ₽ переменных затрат за три месяца, но неверные общие затраты, «экономия 70–90 тыс. ₽» без основания и заявление о сохранении файлов, хотя записи не было. |
| Второй редактор получает одно и то же письмо, два ответа | [L0-1](runs/L0-1.md) и [L0-2](runs/L0-2.md) предлагают перефразировать, но оставляют и ожидание готовой даты, и обещание сообщить отдельно. Первый дополнительно предлагает сказать, что работа уже началась, тогда как время на неё только выделено. | [L1-1](runs/L1-1.md) и [L1-2](runs/L1-2.md) с `challenge.md` оставляют исходное письмо. Проверяют, названа ли *конкретная дата*, а не обещала ли команда *дать дату*. Оба прямо оправдывают фразу «напишем отдельно». Полезное описание сводки по понедельникам из CSV снимать не требовалось. |

**Контроль экономики:** в течение трёх месяцев 30 платящих аккаунтов пилота дают `3 × 30 × (6000 − 4800) − 180000 − 3 × 20000 = −132000 ₽` против **+165000 ₽** при прежней ставке 1500. У ручного сервиса при своих 20 аккаунтах `3 × 20 × (3500 − 2200) − 15000 − 3 × 5000 = +48000 ₽`. Чтобы покрыть свои затраты, пилоту нужно 67 аккаунтов, платящих все три месяца. Чтобы сравняться с ручным сервисом при зафиксированных сценариях 30 против 20, нужна ставка поставщика **2800 ₽**. Ни один из четырёх текстов не дал тройку «результат пилота, результат альтернативы, окупаемость». Интервью не подтверждают число покупателей.

**Контроль письма:** [план команды](../grok-pilot/letter-inputs/planning.md) говорит лишь «Оценка внедрения и даты выпуска будут обсуждаться после исследования». Это ни обещание готовой даты, ни обязательство рассылки. Достаточно оставить рабочую часть письма, а конец заменить на **«Прямого подключения к кассе пока нет. Срок подключения не определён»**. Это наша правка, не результат модели. Второй читатель (отдельный Codex) получил источники и восемь текстов в перемешанном порядке, без обозначений условий. Его разбор подтвердил ошибки периодов/порогов и сохранение лишних обещаний. Независимой проверки человеком не было.

## Затем — сможет ли модель сама открыть файлы и вызвать калькулятор?

Дополнительная пара **после чтения восьми ответов**, не часть начального теста. Та же модель и вопрос об экономике. В обоих диалогах доступны только `read_files` по перечисленным точным путям и арифметика `calculate`; содержание входов не подставляется. В F1 системный текст дополнен действующим `AGENTS.md`, перечислены также BIBLE, повестка и навыки. Это ограниченный стенд на нативных функциях GigaChat, не Cursor, не вся папка и не запуск CLI Стратега. Кто выбирал действие, видно в журналах.

- **[Без папки](tool-runs/F0.md) · [журнал](tool-runs/F0.jsonl).** Дважды запросил имена без `inputs/`, получил два отказа и попросил заново загрузить данные. Содержимое файлов ему не выдавалось. Это промах навигации по нашему строгому интерфейсу, не отсутствие исходных файлов.
- **[С папкой](tool-runs/F1.md) · [журнал](tool-runs/F1.jsonl).** Одним запросом действительно получил таблицу, описание продукта и поправку. BIBLE и отдельные навыки не открыл. Затем заказал два вычисления; для пилота — `(6000+4800)*30-180000-20000*3`. Калькулятор вернул математически верные **84000**, но в формуле издержки *прибавлены* к цене, а доходная часть взята *за один месяц*. Ошибка повторилась и в формуле альтернативы. Из двух одинаковых чисел модель вывела ложную эквивалентность вариантов. Один успешный вызов инструмента не удостоверяет экономический смысл его аргументов.

## Время, расходы и воспроизведение

В основной восьмёрке один вызов SDK занимал **0,64–2,71 с**. На первом прогоне экономики API сообщил `prompt_tokens` 948 без методик и 4174 с ними (в обоих `precached_prompt_tokens=0`). Повторы могли пользоваться кешем, это отражено отдельным полем API. Счёт в рублях API не вернул; денежную стоимость не выводим из счётчиков. Это не сравнение времени с многошаговыми сеансами [Grok в Cursor](../grok-pilot/README.md).

Для повтора нужны Python 3.10+, SDK `gigachat==0.2.3` в своей среде и действующий доступ к указанной модели. SDK читает авторизацию из обычного защищённого окружения; **не помещайте ключ в файлы проекта**. С корня репозитория:

```sh
python docs/gigachat-pilot/run.py /tmp/giga-prompts-new
python -B docs/gigachat-pilot/tool_pair.py /tmp/giga-tools-new
```

Каталоги должны быть новыми; команды расходуют квоту. Если стандартный набор CA вашего Python не доверяет серверу, передайте `--ca-bundle /путь/к/доверенному-системному-набору.pem`. На этой машине каталог моделей ответил с системным CA; TLS не отключался и настройки установки не менялись. При первом старте из изолированного процесса без переданной авторизации произошёл `AuthenticationError`, [запись](answers/E0-1.json); она не является ответом модели. После передачи сохранённой настройки SDK получил все ответы в `runs/` и `tool-runs/`. Маршрут проверен только для этих вызовов, не для Main или субагента в Ouroboros.

**Что делать с результатом:** не использовать испытанную конфигурацию как единственный источник экономического вывода или разрешение на отправку письма. Следующий полезный эксперимент — дать агенту инструмент, который различает цену, переменную стоимость, разовые затраты и период, и проверить его на новых кейсах с другой структурой платежей. Этот инструмент в данном пилоте не испытывался. Одинаковое письмо можно дать другой модели тем же скриптом в отдельном протоколе; нынешний опыт не ранжирует семейства моделей.
