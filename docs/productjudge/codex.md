# ProductJudge-Bench: две полные серии через Codex CLI

18 ноября 2026. **На 24 публичных задачах инструкции Стратега не исправили ни одного основного решения у GPT‑6.2 Astra и GPT‑5.6 Sol.** Без инструкций у Sol уже было 24 верных ответа. С ними она ошиблась в одном случае; у Astra осталась та же ошибка в обоих условиях. Это результат применения *готовой политики*, а не тест всей работы руководителя продукта.

| Маршрут Codex, effort `medium` | Верные основные решения A → B | Улучшилось / без изменения / ухудшилось | Штатный Decision A → B | Штатный Overall A → B |
|---|---:|---:|---:|---:|
| `gpt-5.6-sol` | 24 → 23 из 24 | 0 / 23 / 1 | 100 → 96,875% | 100 → 90% |
| `gpt-6.2-astra` | 23 → 23 из 24 | 0 / 24 / 0 | 96,875 → 96,875% | 89,17 → 89,17% |

A — обычная постановка задачи; B — тот же вход плюс [BIBLE](../../BIBLE.md) и [методика сравнения вариантов](../../skills/compare-options/SKILL.md). Основное решение — полный балл по `g1`; `Decision` взвешивает семейства, а `Overall` учитывает и другие измерения. Падение Overall на 10 п.п. у Sol **не означает десять ошибок**. Все 96 первых ответов приняты штатным парсером, так что столбцы до и после форматного ремонта совпали. Из применимых поэлементных оценок у Astra не изменилось ни одной; у Sol изменились только ветвь и главная проверка одного сценария.

### Один договор — три реакции на одну инструкцию

В `messy-renewal-001` до продления договора 60 дней, проверка безопасности пройдена. Команда должна решать, стоит ли выделить разработчиков на пакет функций. По политике клиента сумма от $120 тыс. меняет действие с «отложить» на «разрабатывать». В документах — два противоречивых пересказа о бюджете и нет письменного обязательства финансового директора. Нельзя подставлять ноль вместо неизвестной суммы.

- [Sol без инструкции](Sol/predictions.jsonl#L13) запросила у финансового директора письменное подтверждение бюджета. [С инструкцией](Sol/predictions.jsonl#L14) выбрала `defer`, как будто исход уже определён. Ответ был валидным JSON; это ошибка решения, не формата.
- [Astra](Astra/predictions.jsonl#L13-L14) задала правильный вопрос в обоих условиях. Её единственная ошибка в основном решении была в другом сценарии (`messy-featureask-002`), также в обоих условиях.
- [Ранее у Grok](Grok/predictions.jsonl#L13-L14) на **этом же сценарии** переход был обратным: `defer` → `q-budget`. Это сравнение конкретной пары, не сравнение результатов полной серии: у Grok были доступны только 9 пар из 24.

**Практический вывод:** не выдавать пример с Grok за общее свойство промпта. Для задачи с явно заданным правилом и коротким форматом ответа я бы начинал без дополнительной методики. В отдельном опыте имеет смысл проверить одну узкую подсказку: «если два источника спорят, изменит ли недостающий факт действие?». Не подбирать её на этих же ответах и называть проверенной на новых данных.

### Что именно было запущено

- Та же ревизия [ProductJudge-Bench](https://github.com/opheleon/ProductJudge-Bench/tree/3732c9a05080e8a6d0de424a626beb8fd4b149d9), автор Christian Ciabattoni, код MIT, публичные сценарии CC BY 4.0. Штатный `validate`: 24/24. Два `prepare.json` побайтно совпали с заданиями прошлой серии Ultra. Условия Codex зафиксированы до его запусков в `29e3e09`.
- Локальный `codex-cli 0.170.0`, app-server по stdio, отдельная временная пустая папка и новый ephemeral thread для каждого ответа, read-only. Проверяли модель и число загруженных файлов-инструкций (0) в `thread/start`, итоговый статус и отсутствие вызовов инструментов в наблюдаемых событиях. Метки — свидетельство CLI, не независимая аттестация бэкенда. Для обоих условий одна нейтральная просьба отвечать по тексту и без инструментов. Вход B длиннее, роли объединены в текст; скрытые инструкции CLI и параметры семплирования не уравнены с чистым GigaChat API.
- Другие попытки: [Composer 2.5 и Gemini 4 Carbon Medium через Cursor](cursor-starts.json). По одному первому запросу A: `init` назвал модель, затем код выхода 1, финального ответа нет. Причина не установлена, пары не получены, оценки не выставляли.
- Счётчики Codex, включая контекст оболочки: Sol **347 334 → 373 173** токена (A → B), Astra **397 012 → 422 907**. Это **1 540 426** токенов всего за 96 ответов; счётчики не являются счётом к оплате. Денежная стоимость не раскрыта. Один повтор, набор публичный; различия объясняют эти прогоны, не средний эффект на новых задачах.

Пересчёт **без модельных вызовов** из корня репозитория, с Python и `PYTHONPATH` для закреплённого upstream из [протокола](../../evals/productjudge/README.md):

```bash
python evals/productjudge/replay.py "$SPLIT" docs/productjudge/raw/Sol.jsonl /tmp/pj-sol-replay --model gpt-5.6-sol
python evals/productjudge/replay.py "$SPLIT" docs/productjudge/raw/Astra.jsonl /tmp/pj-astra-replay --model gpt-6.2-astra
```

Выходные каталоги должны быть новыми. `replay.py` восстанавливает ответы из журнала, сверяет хеши сообщений и текста, который передавали CLI, и запускает штатный `grade`. Для нового **живого** опыта на каждой модели отдельно: `bridge.py prepare`, `codex_collect.py "$RUN/prepare.json" --model <id>`, `bridge.py repairs`, `codex_collect.py "$RUN/repairs.json" --model <id>`, `bridge.py assemble ... --model <id>`; для `bridge.py` указывают пути `$SPLIT` и `$RUN`, как в протоколе. Не переиспользовать папку уже начатой серии.
