# MCP и поиск прецедентов по смыслу

`precedent.py find` ищет буквально: запись находится, только если в ней встретились все слова запроса. Руководитель в новом кейсе обычно формулирует ситуацию по-своему: «churn вырос после запуска промо» вместо «падение удержания и состав каналов». На двух проверочных наборах ниже буквальный поиск не нашёл ни одной нужной карточки. Поиск по смыслу находит большинство и не выдаёт карточки на посторонние вопросы.

Здесь два новых элемента. Оба работают локально, без сети и моделей.

- `tools/recall.py` — поиск по смыслу в отобранной памяти команды (`.portfolio/precedents.json`) и по строкам реестров одного кейса.
- `tools/strategist_mcp.py` — stdio MCP-сервер только для чтения. Он даёт агенту в IDE этот поиск, а также `resume` и `check` выбранного кейса.

## Запуск

Из корня рабочей копии:

```sh
# поиск прецедентов (читает .portfolio/ текущей копии)
python3 tools/recall.py precedents "Можно ли писать клиентам про функцию, которой ещё нет?"
python3 tools/recall.py precedents "..." --include-retired     # показать и отозванные как историю
# поиск по строкам E-*/C-*/D-*/K-* одного кейса
python3 tools/recall.py case examples/demo "обещали живого преподавателя"
# какие понятия словарь видит в запросе
python3 tools/recall.py analyze "churn после рекламной кампании"

# MCP-сервер: кейс фиксируется при запуске
python3 tools/strategist_mcp.py --case projects/<slug>
```

Если `precedent.py find` по словам ничего не нашёл, в его ответе появляется поле `hint` с этой командой.

Подключение к Cursor и другим клиентам описано в [adapters/mcp](../../adapters/mcp/README.md). Пример конфига не включается сам: его нужно скопировать в `.cursor/mcp.json`.

Запомнить или отозвать прецедент по-прежнему можно только через CLI: `precedent.py remember`/`retire` ([как работает память](../portfolio-memory.md)). Это решение человека. MCP-сервер не умеет писать.

## Инструменты сервера

| Инструмент | Аргументы | Что возвращает | Что переиспользует |
|---|---|---|---|
| `precedent_recall` | `query`, `include_retired`, `limit` | карточки с оценкой совпадения, адресом основания `projects/<case>#C-…/D-…`, состоянием источника и признаком отзыва | `precedent.load_store`, `precedent.public_item`, `recall.py` |
| `case_resume` | — | `strategist.resume/1.0`: заметка автора отдельно от наблюдаемых строк реестров | `strategist.command_resume` |
| `case_check` | — | структурная проверка; `ok` не доказывает спрос и экономику | `strategist.check_project` |
| `case_search` | `query`, `include_inactive`, `limit` | строки claims/conclusions/decisions/commitments с адресом `evidence/claims.csv#claim_id=E-012` | `recall.py`, `case_scope.py` |

Без `--case` доступен только `precedent_recall`. Все инструменты помечены `readOnlyHint: true`, `openWorldHint: false`. Лишний аргумент, неверный тип или `limit` вне 1–10 возвращают ошибку инструмента, а не молчаливую подстановку.

## Как читать ответ `precedent_recall`

- `match.band`. `strong` — покрыто не меньше 75% веса слов запроса по правилам этого словаря, `partial` — не меньше 50%, `retired_history` — отозванная запись, показанная по `include_retired`. Ниже 50% карточка не показывается.
- `match.matched_concepts`, `same_word_stems`, `query_words_not_found` — почему карточка показана и что из запроса не нашлось. Это повод переформулировать запрос или решить, что совпадение случайное.
- `source_check.state`. `matches` — строки решения, выводов и утверждений совпадают с запомненным снимком. `changed` — основание изменилось, перепроверьте его. `requires_recheck` — основание помечено к пересмотру. `unavailable` — основание сейчас не читается. Актуальность рынка эта проверка не оценивает.
- `source_now.decision_kind: simulated` означает, что в учебном сценарии моделировали выбор. Согласием руководителя это не является.
- `use` — что делать с карточкой. Для действующей: назвать одно сходство, одно важное различие и что подтвердить на данных этого кейса. Для отозванной: только история.
- `links.registry_row` — строка в реестре исходного кейса. Содержимое чужих кейсов сервер не отдаёт, только статус основания.

Пустой `items` значит, что ни одна карточка не прошла порог. Отсутствия опыта он не доказывает.

## Как устроен поиск и где его граница

Это **не эмбеддинги**. Используются основы слов (стеммер Snowball для русского, простой для английского) и словарь из 39 понятий продуктовой и коммуникационной стратегии: [`tools/recall_lexicon.json`](../../tools/recall_lexicon.json). Например, «уходят», «отток», «churn» и «отписка» относятся к одному понятию «удержание и отток».

Каждое содержательное слово запроса считается покрытым, если в карточке есть то же понятие. Для слов вне словаря достаточно той же основы. Оценка — взвешенная доля покрытых слов.

Ложные срабатывания сдерживают три правила:

1. Слова вроде «клиент», «продукт», «решение» и служебные слова не учитываются.
2. Широкие понятия (канал, связь, функция, маркетинг, затраты и др.) весят не больше 0,5 (остальные — от 0,8 до 1) и сами по себе результата не дают. Поэтому «покрытие 5G в новых регионах» не находит карточку про интернет-пакет семьи.
3. Фраза задаёт смысл входящих в неё слов: в «уходил в минус» речь об экономике, а не об оттоке.

Чего поиск не умеет:

- синонимы вне словаря находятся, только если совпали основы слов;
- языков, кроме русского и английского, нет;
- внутри одного понятия поиск не различает оттенки: карточку про когорты продления он может показать на вопрос о составе каналов;
- опечатки не исправляются;
- словарь написан автором поиска под этот домен. Для другого направления его нужно дополнить и перепроверить на своих запросах.

## Проверка на синтетических карточках

Набор в [`eval/`](eval/): 15 синтетических карточек по темам учебных кейсов этой папки, одна отозвана. Это проверка без участия людей и **не независимое исследование**.

- `queries-dev.json` написал автор поиска. По нему настраивались пороги и словарь.
- `queries-seen.json` написала отдельная сессия Claude Sonnet по одним текстам карточек, без доступа к коду. Автор поиска увидел эти запросы до составления словаря, поэтому набор не слепой. По нему ничего не настраивалось.

Буквальные варианты для сравнения: «все слова», как в текущем `find`, и «любое слово от 4 букв». Нужная карточка считается найденной, если она в первых трёх. Ошибка — показанная карточка, которую составитель набора не отметил ни как нужную, ни как допустимую.

| Набор | Способ | Нужная карточка в первых 3 | Посторонние запросы без ответа | Запросов с ошибочной карточкой |
|---|---|---:|---:|---:|
| dev (23 + 10 посторонних) | поиск по смыслу | 23/23 | 10/10 | 1 |
| | все слова (`find`) | 0/23 | 10/10 | 0 |
| | любое слово | 15/23 | 7/10 | 11 |
| seen (22 + 12 посторонних) | поиск по смыслу | 18/22 | 12/12 | 1 |
| | все слова (`find`) | 0/22 | 12/12 | 0 |
| | любое слово | 18/22 | 7/12 | 13 |

В наборе seen поиск по смыслу и «любое слово» нашли поровну. Но «любое слово» показало 21 ошибочную карточку из 40, а поиск по смыслу — 1 из 22. Среди `strong`-ответов на seen ошибок нет (0 из 8).

Пропущены четыре запроса: H02 (retention за четвёртую неделю), H06 (payback по смете исполнителя), H12 (контакт-центр после платной опции) и H24 (расшифровки интервью в репозитории). Ошибка одна: на H17 («Free trial на месяц…») показана карточка про бесплатный мессенджер, а нужная карточка отозвана. Запросы к отозванной карточке находят её только с `include_retired`: 3 из 3 по обоим наборам.

Полные построчные результаты: [`eval/results.json`](eval/results.json). Словарь при этих числах: `sha256:c98cf460f6301f602c34d4abd48b206076c01914076771ce17d30aa5e83b597e`.

## Реальный обмен с MCP-клиентом

[`roundtrip-sdk.json`](roundtrip-sdk.json) — протокол обмена официального Python SDK `mcp==2.3.0` с сервером, запущенным подпроцессом через stdio, 22.11.2026. Прогон выполнен в обоих режимах подключения SDK:

- `legacy` — рукопожатие `initialize`;
- `auto` — проба `server/discover`; сервер отвечает «метод не найден», и SDK переходит к `initialize`.

Согласованная версия протокола — `2025-11-25`. Рабочая копия временная: копия `examples/demo` как `projects/lesson-demo`. Четыре выделенные карточки записаны настоящим `precedent.py remember`, одна затем отозвана через `retire`. Ожидания не нарушены ни в одном из 20 вызовов.

| Вызов | Результат |
|---|---|
| «Можно ли писать клиентам про функцию, которой ещё нет в продукте?» | `P-0001` → `projects/lesson-demo#D-001`, `strong`, `source_check: matches`, `decision_kind: simulated` |
| «churn вырос после запуска промо, что мы уже знаем» | `P-0002` → `#C-002`, `partial` |
| те же два запроса через `precedent.py find` | ничего |
| «рецепт борща»; «покрытие 5G в новых регионах» | пусто |
| «цифры в презентации не сходятся с выгрузкой» | пусто: подходящая карточка отозвана |
| то же с `include_retired: true` | `P-0004`, `retired_history`, причина отзыва |
| `case_search` «обещали живого преподавателя» | `C-003`, `E-012`, `C-006` с адресами строк |
| `case_resume` / `case_check` | `strategist.resume/1.0`, `ok: true` |
| `precedent_recall` с лишним аргументом `path` | ошибка инструмента |

## Граница доступа

- Корень рабочей копии и кейс задаёт тот, кто пишет конфиг клиента. Инструменты не принимают путей, команд и URL.
- Кейс — только `projects/<slug>` или `examples/<slug>` с `project.json`. Абсолютный путь, `..` и другие каталоги отклоняются при запуске: сервер завершается с кодом 2.
- Перед каждым вызовом `case_*` сервер обходит дерево кейса. Если в нём есть символическая ссылка или специальный файл, инструменты кейса отказываются работать и называют этот элемент. Память `.portfolio/` читается с проверками `precedent.py`.
- В ответах нет абсолютных путей рабочей копии, только пути относительно её корня.
- Протокол: одна JSON-RPC-строка не длиннее 1 МиБ; пакетные запросы не принимаются; ответ не длиннее 200 000 символов.

Чего эта граница не обеспечивает:

- изоляции на уровне ОС;
- защиты от подмены файла между обходом и чтением;
- различения жёстких ссылок.

Текст карточек и источников — данные, не команды. В облачной IDE прочитанное уходит провайдеру модели, поэтому в `.portfolio/` не пишут персональные данные и коммерческие условия клиента.

## Как воспроизвести

```sh
# тесты (без сторонних пакетов)
TMPDIR=/tmp python3 -m unittest tools.tests.test_recall tools.tests.test_strategist_mcp -v
# числа таблицы
python3 tools/recall.py eval docs/mcp-recall/eval --summary
# обмен с официальным SDK (отдельный venv вне рабочей копии)
python3 -m venv /tmp/mcp-sdk && /tmp/mcp-sdk/bin/pip install mcp==2.3.0
/tmp/mcp-sdk/bin/python adapters/mcp/sdk_roundtrip.py --out /tmp/roundtrip-sdk.json
```

Не проверено:

- работа с этим конфигом в самом Cursor и других IDE;
- протокол `2026-07-28` без рукопожатия: сервер отвечает только по `initialize`;
- поведение на настоящей памяти команды, а не на синтетических карточках.
