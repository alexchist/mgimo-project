# Проверка цифры перед планёркой

18 ноября 2026. Идея из [`verify_and_record` Ouroboros](https://github.com/razzant/ouroboros/blob/4be731ffcd2990acff55fb746b0daa073c22d5af/ouroboros/tools/verify.py): отделить «команда что-то вычислила» от «число в записке выдержало проверку». Мы не копировали исполнение произвольных команд: для простой экономики подписки есть одна формула, именованные входы и, по желанию, локальный JSON с результатом сравнения. Формула проверяет сценарий, не бизнес-решение.

## Ошибка, ради которой это сделано

[Lightning в F1](../gigachat-pilot/tool-runs/F1.md) написала «84 000 RUB прибыли» и для пилота, и для ручной альтернативы. [Тогдашний калькулятор](../gigachat-pilot/tool-runs/F1.jsonl) вычислил именно то выражение, которое ему поручили. Для сегодняшней сверки я взял [исходную таблицу](../../evals/cases/decision-economics/economics.csv), заменил в отдельной [копии](corrected.csv) ровно одно поле — `paid_pilot.variable_cost_per_account_month_rub`, 1500 → 4800 по [поправке поставщика, строка 2](../../evals/cases/decision-economics-update/supplier-update.md#L2). Три месяца — из [брифа](../../evals/cases/decision-economics/brief.md#L3). Входы синтетические. Из корня:

```sh
python3 tools/economics.py docs/verification-pilot/corrected.csv --months 3 \
  --expect-net paid_pilot 84000 --expect-net manual_service 84000
```

Код **1** здесь ожидаем: обе суммы не совпали. В [фактическом результате](historical-check.json) видны две строки расчёта: **−132 000 ₽** при 30 аккаунтах пилота и **+48 000 ₽** при 20 аккаунтах ручного сервиса. Для пилота нужны **67** платящих весь срок. До поправки по исходной таблице было **+165 000 ₽**. Расходы вычитаются, разовая настройка — один раз, ежемесячная часть — три. Обе версии отдельно сверены сложением месячных потоков. Это ретроспективная проверка двух фраз из настоящего ответа, **не** повторный вызов GigaChat и не доказательство, что модель сама выберет верные входы.

## Выберет ли инструмент свежий агент?

Двум отдельным сеансам Codex CLI (запрошены `gpt-5.6-sol`, medium, ephemeral, read-only) дали [один запрос](request.txt) и [одинаковый новый CSV](new-case.csv) в `materials/scenarios.csv`. Оба видели рабочие инструкции и инструменты: A — из `1a647f7`, B — с добавленными `economics.py`, его локальной справкой и ссылкой в навыке анализа. Не подсказывали имя команды. В обеих отдельных папках: AGENTS, BIBLE, README, методы, промпты, шаблоны и инструменты, без ответов предыдущих пилотов и тестов; это короткий вопрос не про готовый кейс. Запись/сеть для решения не требовались. Файлы в папках побайтно не изменились; статусы процессов — 0. Источники ниже — финальные сообщения и проекции команд, не полные сеансы. Временные пути в оригинальных ответах относились к их рабочим копиям.

| | A: прежняя папка | B: с инструментом |
|---|---|---|
| Результат | [−5 400 / +9 400 ₽, порог 39](A-answer.md) | [те же значения](B-answer.md) |
| Основание | [2 команды](A-commands.json), собственная формула в `awk` | [4 команды](B-commands.json); утилита [сверила обе фразы](B-calculation.json): плюс для подписки ошибочен, сумма ручного сервиса совпала |
| Время одного запуска | 27,2 с | 35,6 с |

**Ничья по ответу.** Новое действие — явное сравнение, которое другой читатель может повторить, не переписывая формулу. Не выигрыш в точности, времени или цене. Более того, B сначала попытался вызвать `profile` без обязательного `--output` (код 2). После опыта в навыке уточнили, что для такой справки профиль с записью не нужен. Этот текст после уточнения новым A/B не проверяли. Один запрос и один запуск на условие, Linux, не GUI и не проверка с людьми. Денежная стоимость неизвестна.

Для офлайн-повтора B: `python3 tools/economics.py docs/verification-pilot/new-case.csv --months 4 --expect-net subscription 5400 --expect-net manual 9400` (код 1); без двух `--expect-net` будет только расчёт. При сохранении в кейс используйте `--receipt` с новым именем. Откуда взялись цена, срок и число аккаунтов и можно ли применять эту модель платежей, по-прежнему нужно проверить по первоисточникам.

## Отдельный опыт: можно ли верить старой версии стратегии?

Брали новую одноразовую копию `examples/demo` для каждой версии CLI. После `revise` меняли текущую стратегию, затем один байт архивной без изменения размера, затем убирали файл из проверяемого снимка. [Полные строки результата для `check` и `resume`](snapshot-checks.json) — этап, команда, код выхода, структурный `ok`, статус архива и типы расхождений. Версия `1a647f7` вернула `ok` во всех четырёх состояниях; новая — только при целых архивных документах. Правка рабочей стратегии допустима у обеих. В старой части самого демо уже есть ревизия без описи: она не становится проверенной при открытии новым CLI. [Повторить опыт](replay_snapshot.py): `python3 docs/verification-pilot/replay_snapshot.py` из корня; дополнительный аргумент — путь к прежней версии `strategist.py`. Проверка программы, а не тест реакции модели на повреждение; оригинальный кейс не меняется.
