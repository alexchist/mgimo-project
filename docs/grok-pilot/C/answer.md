Проверю черновик рассылки по материалам в этой папке: сначала принципы из корневой конституции, затем сам текст и документы команды. Файлы не меняю и ничего не отправляю.Черновик обещает повторные заказы, срок подключения кассы и понедельничный отчёт. Сверю каждое обещание с таблицей и документами команды по единицам, знаменателю и тому, что продукт уже умеет.Черновик в текущем виде отправлять нельзя. Из трёх обещаний клиенту выдерживает только понедельничная сводка, и то с другим источником данных, чем следует из текста.

## Что говорит черновик

> «По итогам пилота 80% всех мастерских вернулись за вторым заказом. Подключим вашу кассу за четыре дня; отчёт будет приходить по понедельникам на почту».

## Повторные заказы — убрать

80% в таблице есть только как 4 из 5. Это не доля всех мастерских и не повторный заказ.

В `inputs/followup.csv`:

| metric | count | period |
|---|---|---|
| invited_workshops | 25 | October |
| workshops_with_first_order | 10 | October |
| interviewed_after_first_order | 5 | November |
| interviewed_saying_they_intend_second_order | 4 | November |

4 / 5 = 80% — столько опрошенных в ноябре **сказали, что намерены** сделать второй заказ. Опрошены 5 из 10 мастерских с первым заказом в октябре и 5 из 25 приглашённых. Намерение в интервью не является выполненным заказом. В `inputs/planning.md` прямо сказано: телеметрия повторных заказов ещё не подключена, то есть возврат за вторым заказом команда не измеряла. Периоды тоже разные: заказы — октябрь, интервью — ноябрь.

В рассылку эту цифру не переносить. Единственная точная фраза для внутреннего разбора: «в ноябре 4 из 5 опрошенных мастерских с первым заказом сказали, что намерены заказать ещё раз». Для клиента это не доказательство возврата.

## Срок подключения кассы — убрать

«Подключим за четыре дня» не следует из плана. В `inputs/planning.md` четыре **рабочих** дня зарезервированы на изучение API кассы. Оценку внедрения и дату выпуска команда будет обсуждать после этого исследования. В `inputs/release.md` прямого коннектора к кассе в ноябрьской версии нет. Четыре дня изучения API нельзя обещать как срок подключения.

## Понедельничный отчёт — оставить, сузив формулировку

Это единственное обещание, которое уже выполняется. В `inputs/release.md`: в ноябрьской версии еженедельная сводка продаж уходит по понедельникам на электронную почту. Источник — CSV, который загружает пользователь, а не касса. В черновике фраза стоит сразу после «подключим кассу», поэтому клиент прочитает отчёт как следствие подключения. В письме нужно назвать и день, и содержимое (сводка продаж), и источник (загруженный CSV).

## Редакция для клиента

Здравствуйте.

В ноябрьской версии по понедельникам на электронную почту приходит еженедельная сводка продаж. Она собирается из CSV, который вы загружаете сами.

Прямого подключения к кассе в этой версии нет. Срок подключения сейчас назвать нельзя: команда сначала изучает API, и только после этого появится оценка внедрения и дата выпуска. Когда оценка будет, напишем отдельно.
