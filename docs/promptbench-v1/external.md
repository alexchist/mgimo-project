# Нужен ли собственный бенчмарк?

Есть полезные готовые наборы; у каждого другое измеряемое умение. Проверено по первоисточникам 18.11.2026. В этой серии **не запускали** чужие задания, не копировали их сценарии, баллов на их шкалах у нас нет.

| Первоисточник | Когда выбрать вместо своего теста | Что не переносится |
|---|---|---|
| [ProductJudge-Bench, авторский README](https://github.com/opheleon/ProductJudge-Bench) | Самое близкое: по явным правилам принять решение, расставить приоритеты при лимите, построить / настроить / отложить или запросить недостающий факт. Проверка механическая. Особенно ценны пары: изменение ключевого факта должно перевернуть решение; перестановка текста и нерелевантный шум — нет. | Сам автор исключает изобретение стратегии, убеждение и управление заинтересованными сторонами; 24 задачи в опубликованном пилоте — не промышленный рейтинг. README называет MIT / CC-BY-4.0, а `DATA_LICENSE` упоминает соседний проект: перед распространением данных уточнить у автора. |
| [BizBench, статья](https://arxiv.org/abs/2311.06602) | Какую часть количественной задачи провалила модель: извлечение величин, формулу или вычисление? Полезный независимый контроль финансового рассуждения. | Написание исполняемого кода и финансовая предметная область — не текстовая записка российскому руководителю, не коммуникационная стратегия. Лицензию на повторное распространение данных здесь не устанавливали. |
| [DeepResearch Bench](https://github.com/Ayanami0730/deep_research_bench) | Нужна внешняя проверка отчёта исследовательской системы: качество исследования отдельно от поддержки утверждений ссылками. RACE и FACT оценивают разные стороны результата. | Английские/китайские исследовательские задачи и дополнительные судьи/извлечение страниц. Не измеряет, разумно ли пересмотрен уже принятый выбор после нового договора. |
| [BrandEval](https://github.com/htgan-ai/BrandEval) | Кризисные сообщения и развитие реакции аудитории; образец изменения обстановки во времени. | Симулированные реакции не поведение клиентов. Авторский README прямо предупреждает, что механизм динамической оценки в опубликованном симуляторе отличается от статьи. |
| [Promptfoo: Select Best](https://www.promptfoo.dev/docs/configuration/expected-outputs/model-graded/select-best/) | Организовать сравнительные прогоны промптов и отдельно задать судью. Это инфраструктура, **не набор валидированных продуктовых задач**. | Выбор «лучшего» не означает, что хоть один ответ пригоден; в нашем стенде разрешены и ничьи, и два провала. Интеграция Promptfoo с GigaChat здесь не испытывалась. |

**Выбор:** для внешнего контроля фиксированных решений первым взять ProductJudge-Bench без изменений и считать результат отдельно. Для нашего русскоязычного продукта нужны также свои разноформатные материалы, буквальное сообщение клиенту, история выбора и пересмотр; внешняя таблица не измеряет пользу наших инструкций. Здесь первая сопоставимая серия — именно текстовый тест. Следующий внешний набор и новые закрытые сквозные случаи нужно зафиксировать до следующей доработки промптов.
