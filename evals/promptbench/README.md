# PromptBench-RU v1: меняется инструкция, не задача

Проверяем добавочную пользу **настоящих прикладных текстов Стратега**, а не знание фактов из интернета и не способность IDE работать с файлами. Ни один предыдущий ответ или кейс пилотов не включён. Все десять сценариев написаны для этой серии; типы ошибок известны разработчику по старым прогонам. Это открытый regression set, не секретный holdout и не универсальный рейтинг LLM.

## Зафиксировано до вызовов

- Три строки одного нативного GigaChat API: **3-Pro, 3-Ultra, 3-Lightning**. Не подменять недоступную, сверить версию каждого ответа. 10 задач × 3 модели × 2 условия × 2 повторения = максимум 120 ответов. Не расширять серию по ходу для «удачного» результата. На первом исключении SDK остановить **эту строку модели**, записать неподанные запросы, продолжить остальные. Исключение не доказывает, что запрос не стоил токенов.
- **A:** добросовестная краткая инструкция продуктового помощника; **B:** A + полный `BIBLE.md` и один заранее выбранный навык/промпт для задачи, без переписывания правил под ответ. Состав в `cases.json`; зафиксировать Git SHA инструкции/кейсов/ключа/рубрики до сбора. Выбор навыка здесь дал экспериментатор, не модель. Это не «вся папка» и не поиск внутри неё; эффект длины и содержания не разделяем.
- Одинаковые сообщения пользователя, источники, отсутствие инструментов, температурa 0,2, максимум выхода 1200 токенов, свежая история на запрос. Seed 18011 задаёт только порядок: перемешать блоки (модель, задача); в первом повторе для каждой модели пять пар A→B и пять B→A, во втором инвертировать каждую пару. Никакого общего диалога или обучения на ответе первого плеча. Ни код, ни ключ, ни рубрика в сообщения не входят. Подписки, инфраструктура и тарифы других маршрутов не сопоставимы.
- **Основная мера:** на 8 коротких задачах полное совпадение четырёх требуемых полей. Точные типы, числа с abs error <1e-6, допустимы JSON и обрамление ```json; регистр значений значим, дополнительные поля не штрафуются. Необработанный текст и незавершённый ответ не проходят контракт; отдельно показать parse success и частичные баллы. `api_error`, неподанные, утраченные записи — пропуск, не ноль знаний. Сравнение только по совпадающим парам (case, rep, model); отдельный case — единица обобщения, не отдельный токен/критерий или повтор. Показать выигрыш/ничью/потерю и разброс по кейсам. Не объявлять статистического победителя по 8 случаям.
- **Открытая мера:** 2 записки с разными задачами, заранее по 5 бинарных критериев и критический риск в `rubric.md`. Перемешать тексты, скрыть условие и модель. Два отдельных контекста оценивают их до раскрытия; сохранить обе серии оценок и расхождения, не выдавать их за голос людей. Идентичный текст можно оценить один раз и сопоставить со всеми его появлениями. Для обеих задач не смешивать качество текста с точностью JSON в общем балле. Время SDK, токены входа/выхода и денежную стоимость отделять; неизвестная стоимость не нулевая.

## Запуск

`python3 evals/promptbench/benchmark.py prompt 09 B` показывает точный payload, без сети и SDK. Из того же checkout его можно подать другому chat API: переносить оба сообщения и настройки, сохранить реально обслуженную версию. Новая модель, инструменты, промпт или корпус — новая серия, не дополнение задним числом.

Для **реальных** вызовов нужен Python 3.10+, `gigachat==0.2.3`, защищённое окружение SDK и доступ к выбранным моделям. Ничего не передавайте в чате или Git. Пример полной серии (потребляет квоту, каталог вывода должен отсутствовать):

```bash
python evals/promptbench/benchmark.py run /tmp/strategist-bench-new --max-calls 120
python evals/promptbench/benchmark.py score /tmp/strategist-bench-new
```

При необходимости укажите `--ca /path/to/trusted-ca.pem`, TLS не отключайте. Дешёвый вариант: `--models GigaChat-3-Pro --repeats 1 --max-calls 20`. `score` — чистый offline-пересчёт, без пакетов, модели и ключа. Ответы с прерванной отправкой не запускаются повторно. Для точного повтора прежней серии сначала переключитесь на указанную в её отчёте ревизию. Опубликованные задачи и проверяющие нашей серии сознательно открыты; старые локальные `evaluator_only/` сюда не входят. Для нового заявленного улучшения зафиксируйте новую версию правил **до** получения новых неразобранных кейсов.
